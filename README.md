# Create: Jet Engines

Modular jet engines for Create Aeronautics that physically propel **Sable** sublevels.

Build an engine out of separate blocks, feed it a redstone throttle, and it applies real force to
the aircraft's physics body — off-centre engines produce torque, symmetric pairs cancel, and thrust
rotates with the airframe.

* Minecraft **1.21.1** · NeoForge **21.1.238** · Java **21**
* Requires **Sable 2.0.3+** (with Sable Companion 1.6.0, bundled inside Sable)
* Designed for **Create Aeronautics 1.3.0** / **Create 6.0.10**, but neither is a hard dependency

## Building an engine

```
Fan → Compressor → Combustion Core → Nozzle
Fan → Compressor → Compressor → Combustion Core → Afterburner → Nozzle
```

* Every module must face the same way. The facing points **downstream**, toward the exhaust.
* 1–4 compressor stages, with diminishing returns per stage.
* The afterburner is optional and sits between the core and the nozzle.
* Thrust pushes **opposite** to the facing, and is applied at the nozzle.

Power the **combustion core** with redstone: signal 0 is off, 1–15 is proportional throttle.
The engine spools up and down gradually; the afterburner only lights once the dry engine is
sufficiently spooled.

An engine will refuse to make thrust if the chain is incomplete, misaligned, or has too many
compressor stages. Blocking the intake heavily reduces thrust; blocking the nozzle kills it.

## Tuning

Everything lives in `config/create_jet_engines-server.toml` — base thrust, compressor scaling,
afterburner multiplier, spool rates, efficiency terms, and a hard per-engine force clamp
(`maxForcePerEngine`) that guards against physics blow-ups.

Set `logPropulsionDebug = true` to log actor firing, sublevel identity, force vector, application
point and throttle once per second per engine.

## Development

```bash
./gradlew build              # production jar -> build/libs/
./gradlew runClient          # dev client, with real Sable on the runtime classpath
./gradlew runServer          # dedicated server
./gradlew runGameTestServer  # runs the automated propulsion tests
```

The dependency jars in `libs/` are the real distributed builds (see `libs/README.md`). They are
`compileOnly` plus `localRuntime`: nothing from them is packaged into the output jar.

### Regenerating assets

Assets are generated, and the generators are the editable source of truth:

```bash
python3 tools/generate_assets.py             # textures, models, blockstates, .bbmodel
python3 tools/generate_sounds.py             # the six .ogg engine sounds
python3 tools/generate_gametest_structures.py # gametest templates
```

Blockbench projects for every model are in `assets_src/*.bbmodel`.
